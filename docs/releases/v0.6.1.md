# v0.6.1 — device mode by default

The root address, `/start` used by older installations, and the install page now open `/offline` directly. Authentication is no longer part of the normal device startup path. Online accounts remain available explicitly at `/cloud`, and sign-in/sign-up continue to open online account workspaces or their invited workspace.

Device-mode links use native anchors with hash destinations instead of Next.js navigation and prefetching. Client/project/task/settings navigation does not request pages or data from the server even while the connection is available. The same UI retains normal Next.js links for cloud workspaces. The local storage format and existing data are unchanged; cloud data still requires an explicit one-time copy to the device.

Validation: lint, formatting, TypeScript and a clean production build passed. The six offline/install browser scenarios passed, plus a focused startup/navigation test verified root and legacy launches, optional cloud sign-in, and zero document/fetch/XHR requests while navigating all five device sections with the network enabled.
