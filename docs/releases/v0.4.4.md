# ArzDesk v0.4.4

- Development assets and authentication share an explicit origin derived from BETTER_AUTH_URL. Set it to the laptop's LAN URL when testing on a phone. Same-port localhost and 127.0.0.1 remain usable in development. Production does not gain these extra trusted origins.
- Credential submit buttons and the cedar wait until client handlers are ready, preventing a tap during hydration from acting as a native reload.
- Authentication forms use a POST-only fallback when client JavaScript has not loaded. The fallback does not process credentials or mutate accounts; it redirects to a visible page-loading error instead of submitting passwords in a GET query. A noscript message explains that JavaScript is required.
- The sign-in page removes legacy password-bearing queries by redirecting to the clean sign-in URL. Previously exposed credentials must still be changed.
- Theme toggling no longer depends on browser animation support.
- No dependency or database migration. Preserve `.env`, change only the existing BETTER_AUTH_URL line for phone testing, clear `.next` and restart. See [phone instructions](../testing-on-phone.ar.md).

## Validation

Production build, ESLint and formatting passed; 30 unit/database/auth tests passed. Touch emulation against an IP origin different from localhost passed theme switching, sign-up, workspace creation, session persistence, Logout and sign-in against the development server. Four production browser flows passed for password recovery, theme persistence/motion, account changes/session revocation and unhydrated POST fallback. The no-JavaScript check uses the actual server-rendered form isolated from Next's streaming reveal scripts. The user's physical phone/network was not directly accessible from this workspace.
