# تجربة ArzDesk على الهاتف — التطوير المحلي

هذه الإعدادات مخصّصة لتجربة نسخة التطوير على شبكة Wi-Fi نفسها. الهاتف يفتح عنوان اللابتوب، وليس localhost الخاص بالهاتف.

1. أوقف السيرفر بـ Ctrl+C، وانسخ ملفات النسخة الجديدة فوق المشروع مع الاحتفاظ بـ `.env` وقاعدة البيانات.
2. في ملف `.env`، عدّل السطر الموجود نفسه ليكون عنوان اللابتوب على الشبكة. مثال لهذه الشبكة:

```dotenv
BETTER_AUTH_URL=http://192.168.1.8:3000
```

لا تضف سطراً ثانياً للمفتاح نفسه. لا تغيّر DATABASE_URL أو BETTER_AUTH_SECRET.

3. من Terminal داخل المشروع نفّذ:

```powershell
if (Test-Path .next) { Remove-Item .next -Recurse -Force }
npm run dev -- --hostname 0.0.0.0
```

4. والهاتف على Wi-Fi نفسها، أغلق التبويب القديم وافتح الرابط من جديد من دون بيانات دخول في العنوان:

```text
http://192.168.1.8:3000/sign-in
```

5. اختبر الأرزة أولاً ثم تسجيل الدخول. حسابك الحالي وبياناتك محفوظة في قاعدة PostgreSQL الموجودة. لا تحتاج إنشاء حساب جديد لمجرد استخدام جهاز آخر. الكمبيوتر يقدر يبقى يستعمل http://localhost:3000 أثناء التطوير.

إذا تغيّر عنوان اللابتوب، حدّث BETTER_AUTH_URL والرابط وأعد تشغيل السيرفر. إعداد Next.js يأخذ اسم المضيف فقط، وإعداد التحقق يأخذ أصل الرابط الكامل؛ كلاهما مشتق من المفتاح نفسه. لا يوجد سماح عام لكل الشبكات، ولا تضاف عناوين التطوير أثناء تشغيل الإنتاج.

إذا ظهرت بيانات اعتماد في رابط أثناء استعمال نسخة أقدم، غيّر كلمة المرور، ونظّف ذلك الرابط من سجل المتصفح. لا ترسل ملفات `.env` أو كلمات المرور أو روابط تحتوي عليها عند طلب المساعدة.
